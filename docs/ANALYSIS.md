# P4 분석·화면 계약

분석은 SQLite 읽기 전용 스냅샷에서 수행한다. 수집 API 호출은 없으며, HTML은 데이터·CSS·JavaScript를 한 파일에 포함한다. 기본 경로는 `.local/real/reports/progress.html`이다. 화면에서 조건을 바꿔도 API를 호출하지 않는다. 데이터 갱신에는 별도 수집과 보고서 재생성이 필요하다.

## 공통 범위와 추적

- 최신 공고 차수 1개를 선택하고 어느 차수든 취소된 공고를 제외한다. 재공고가 가리키는 이전 공고는 실제 저장 번호의 정확 일치 또는 `번호-차수` 형식 일치로 제외한다. 임의의 부분 문자열 연결을 하지 않는다.
- 면허·개찰은 공고번호와 차수를 모두 일치시킨다. 개찰단위의 분할번호와 재입찰 회차를 유지한다. `rbidNo`가 0인 최초 회차만 경쟁 요약에 쓰고, 최초 회차가 없으면 마지막 회차로 대체하지 않는다.
- 지역은 공고 차수 이하의 최신 지역 차수를 명시한다. 차수가 다르면 shortlist에서 별도 확인 대상으로 분리한다. 공백만 정규화하며 지역명 변경이나 현재 주소를 과거 주소로 소급하지 않는다.
- 기간·계약방식·추정가격 구간을 동일하게 적용한다. 법인 상황은 기존 법인 면허 추가 / 신규 법인 / 본점 이전으로 구분해 표시하지만 전체 참가조건 판정은 UNKNOWN이다.
- `notice_keys`, 공고 차수, 면허·지역·개찰 응답 ID, 원공고 URL로 결과를 추적한다. 집계 CSV·JSON과 별도로 `*_notices.csv/json`에 근거 공고를 낸다. CSV는 UTF-8 BOM이고 수식 시작 문자는 무력화한다.
- 현재 분석 확정 코드는 4992다. 다른 `--license` 값은 미검증 기능으로 명확히 거부한다. 점수·순위·낙찰확률·기대매출을 제공하지 않는다.

## 입지 비교

관내 공고와 도 단위 공고를 구분한다. 허용지역 토큰이 본점 주소의 단어 단위 앞부분인 경우만 지역이 일치한다. 같은 공고가 관내와 도 단위에 모두 걸리면 관내로 한 번만 센다. 복수 허용지역에 따른 지역 간 중복은 유지하며 전국 수는 공고 복합키 집합에서 직접 센다.

표본은 최초 개찰단위 수이며 공고 수와 다를 수 있다. 연결률은 최초 회차가 연결된 공고 수 / 해당 지역 대상 공고 수다. 미개찰·미수집·null은 경쟁 수 0이 아니다. 참가업체수는 명부 전체 수이고 유효 경쟁자 수가 아니다.

전체 지역 표의 참가가능지역 연결률이 80% 미만이면 현장지역 기준으로 전환하고 **참가 자격 지역이 아님**을 표시한다. `analyze location --hq`는 지정 본점의 지역 기준 후보를 별도로 반환하며 미기재 공고 수와 연결률을 함께 제공한다.

## 단가계약

공고명에 단가가 있는 공사 중 7자리 수요기관 코드의 첫 자리가 3·4·5·6인 공고를 대상으로 한다. 이는 기관 유형 마스터의 공식 분류를 대체하지 않는 관측 규칙이다. 첫 자리 6은 광역으로, 나머지는 기관명 앞 두 단어로 묶는다. 요구 면허와 허용업종 코드의 관측 비율이며 복수면허 AND/OR를 확정하지 않는다.

## 마감 전 공고와 화면

지역 일치 후보 / 지역 미기재 후보 / 차수·필드 품질 확인 필요를 분리한다. 마감은 KST 현재 시각과 비교하고 정렬한다. 스냅샷 이후 정정·취소 여부, 주력분야·면허 AND/OR·실적·적격심사·주소 기준일은 원공고를 확인해야 한다.

화면은 기간·추정가격·계약방식·본점·법인 상황 필터, 지역/공고 검색, 열별 정렬, CSV 다운로드, 근거 공고 대화상자, 라이트/다크 테마, 모바일 카드 표를 제공한다. 외부 스크립트·폰트·통신은 없고 CSP에서 연결을 차단한다. 자료 약 3.7만 건을 포함한 HTML은 약 33 MB이므로 실제 휴대폰 하드웨어에서의 로딩 성능은 별도 확인이 필요하다.
