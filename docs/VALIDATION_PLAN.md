# 검증·인수 테스트 계획

이 문서는 테스트 요구사항이다. 아래 항목이 이미 통과했다는 뜻은 아니다.
네트워크 없는 단위테스트와 실제 인증된 통합테스트를 구분한다.

## 1. P0 실제 연결 검증

연도(2023·2024·2025·2026), 지역범위(시·도·단일 세부지역·복수지역), 작업유형·공고상태를 달리한 소량 표본을 고른다. 목표 최대 20건, 현재 실행·일별 호출예산을 우선한다. 표본 부족은 보고한다.

각 표본에서 확인할 것:
- 공식 공사 목록과 원문 공고가 일치하는가.
- 면허제한과 주력분야가 어느 응답 또는 원문에 나타나는가.
- 참가가능지역과 발주기관 주소를 구별할 수 있는가.
- 공고 버전·분할단위·개찰회차를 연결할 실제 키는 무엇인가.
- 기초금액의 단위·VAT·총액 여부가 명확한가.
- 개찰 요약 count가 무엇을 포함하는가.
- 참여명부의 모든 페이지를 받으면 같은 의미의 count가 일치하는가.
- 유효·무효·미달·공동수급이 어떤 형태로 나타나는가.
- 개찰순위 1위와 최종낙찰이 별도로 제공되는가.
- 빈 응답이 정상 무자료인지 오류·조건 부적합인지 구분되는가.

공개 PDF 대조는 자격문구·지역의 검증이다. 실시간 개찰명부 또는 공식 결과를 확인하지 못했다면 전체 투찰수 검증으로 기록하지 않는다. 결과 대조 원문이 접근 불가하면 해당 검증항목을 BLOCKED로 둔다.

보고서에 표본 선정방법, 성공·실패·보류 수, 확인한 연도·업무·오퍼레이션, count 정의, 미해결 항목을 쓴다. 응답 원본과 키를 문서에 그대로 붙이지 않는다.

## 3. 인수 기준

P0: 문서·응답 검증 상태가 구분되고 핵심 연결을 실제로 확인했거나, 미검증 사유가 정확하며 실행 가능한 검증 도구가 있다. 키가 없어 도구만 완성됐다면 ‘코드 준비 / 실연동 미검증’으로 인수 상태를 나눈다.

P1: 재실행·재개·원본 재처리·회차/취소 처리·숫자 정의가 테스트된다. 수집범위의 완료 상태와 발견한 누락이 기록된다.

P2: 모든 집계에 기간·조건·표본·분모·단위·자료시점이 있고 원문으로 추적 가능하다. 자격조건 미확인과 낙찰심사가 별도 표시된다. 아직 전국 표본이 부족하면 화면 구현완료와 전국 입지판단 가능을 별도 상태로 보고한다.

지역별 최적 입지에 대한 결론은 테스트 통과 그 자체가 아니라, 실제 비교 가능한 데이터와 사용자 회사조건 검토에 기초해야 한다.
