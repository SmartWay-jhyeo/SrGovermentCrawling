# 목업 구현 대조 — 2026-10-08

사용자가 목업을 채택한 뒤 “디테일은 나중에”라고 지시했다. 주요 레이아웃과 실제 동작을 먼저 구현했으며 픽셀 단위 동일성은 주장하지 않는다.

| 확인점 | 목업 | 구현·관측 | 남은 조정 |
|---|---|---|---|
| 배경·강조색 | 흰 본문, 옅은 회색 메뉴, 파란 주요 동작 | 동일 계열 토큰 적용, 검색·현재 메뉴 강조 | 네이티브 경고색의 미세 차이 |
| 탐색 | 왼쪽 고정 메뉴 6개, 하단 프로필 | 네이티브 버튼과 프로필 선택, 메뉴 이동 검증 | 브랜드 상단 여백·아이콘 크기 |
| 검색 | 긴 검색창, 두 줄 필터, 검색·초기화 | 실제 기간·지역·금액·방식·상태 필터 | 날짜 입력의 네이티브 UI 차이 |
| 결과 | 표, 출처 보조문구, 금액, 검토 상태, 상세 진입 | 실제 DB 결과와 페이지 이동·CSV/JSON 제공 | 실제 긴 기관명·지역명의 밀도 조정 |
| 상세 | 조건 표와 오른쪽 금액·출처, 탭, UNKNOWN | 같은 구조로 구현, 정확한 번호·차수로 진입 | 모든 과거 정정 원문 열람은 미구현 |
| API | 엔드포인트 목록, 요청·응답 패널, 미연결 상태 | 설계 화면과 비활성 연결 테스트 구현 | HTTP 서버·인증은 후속 개발 |
| 모바일 | 별도 이미지 미작성 | 390×844에서 세로 필터·접힌 메뉴, 가로 넘침 없음 | 필터 접기 등 밀도 조정 |

생성 목업 3개와 실제 PC 검색·상세·API 스크린샷을 `view_image`로 확인했다. 스크린샷에는 실데이터가 포함되므로 Git에 넣지 않았다. 로컬 브라우저 근거는 `%TEMP%/bidloc-app-qa/`에 보관했다. 목업 자체는 합성 예시만 포함한다.

앱의 조작 요소는 Streamlit 네이티브 입력·버튼·표·다운로드다. CSS는 외형을 조정하고, 읽기 전용 공고 텍스트는 HTML escape 후 표시한다. 기존 보고서 HTML을 iframe에 넣어 앱처럼 보이게 만든 방식이 아니다.
